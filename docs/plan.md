## Решения (согласовано в грилинге)
1. Отдельный репо `metro-control` в корне `/root/sirius/metro`; `data/raw`, `data/processed`, `runs/` — в .gitignore.
   Исходные файлы переносятся: zip → `data/raw/`, ТЗ/план/README команды → `docs/` (README команды → `docs/team_notes.md`).
2. Стек: Python 3.11 (uv), Streamlit + Plotly, Polars + Parquet, Pydantic 2 + JSON Schema, pytest + ruff. Логика без Streamlit.
3. Контракты v0.1 (`contracts/v0_1/` + JSON Schema + валидные/ошибочные примеры + CHANGELOG): оболочка пакета
   (schema_version, run_id, generated_at UTC, data_mode, manifest с checksum), LineRef, StationEntries, ForecastRow
   (152 строки = 19×8, q10/q50/q90, quantiles_ready), LoadRow, SimulationState, Recommendation, EffectComparison.
4. Загрузчик Excel → `data/processed/station_entries.parquet` (station_id латиницей, interval_start UTC, day_type, entries) — мой; человек 2 может заменить своим через тот же контракт.
5. OD: гравитационная модель; притяжение j = входы j в «зеркальный» период (утро↔вечер, день — сутки), сопротивление по времени в пути;
   пересадочные узлы и все коэффициенты — `config/assumptions.json` с версией. Sanity: пиковый перегон ≤ парность×1458.
6. Загрузка перегонов: статическое назначение (36 направленных перегонов), r = спрос / (отправления × 1458), горизонт контроля +30 мин;
   цвета ≤80 / 80–100 / >100%. 0.85 — только для расчёта требуемой частоты.
7. Симулятор: поездной событийный (heapq), отправления с конечных по базовому графику, фикс. времена перегонов/стоянок, выведенные из оборота 99 мин
   (допущение), очереди по станции×направлению×назначению, высадка→посадка, жёсткая вместимость 1458, дробный детерминированный поток (FIFO-когорты),
   полный день 05:30–01:00. Без блокировки между поездами и манёвров; резерв появляется в Автово/Девяткино через 15–20 мин.
   Спрос (факт) отделён от прогноза; состояние сохраняется между шагами.
8. Mock-прогноз = медиана станция×слот×тип дня (status=mock). Mock-политика = правила ТЗ (r>1 два as_of → резерв/сдвиг пика; r<0.8 три → снять состав;
   ограничения: мин. интервал, 4 резерва, задержка), помечена mock; человек 4 подменяет через адаптер. Исполнитель действий однократен по recommendation_id.
9. Сценарии на реальных днях + наложения: quiet_weekend (реальное воскресенье), rail_surge (будни + приток у Восстания/Ленина), snowfall (февраль, сдвиг пика).
10. Метрики сравнения: пассажиро-минуты ожидания, остаток очереди, отказы в посадке, макс./ср. заполнение, поездо-часы и поездо-км; рубли — от человека 4.
